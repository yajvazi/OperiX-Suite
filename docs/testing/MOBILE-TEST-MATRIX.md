# OperiX Invoice Mobile test matrix

Audit date: 2026-08-19. This matrix was built from the implementation, not only from product documentation. The repeatable audit command is `npm run audit:mobile-test --workspace=operix-invoice`.

The audit found 62 screen files, 63 registered routes, 386 mobile pressable/button sites, 32 text inputs, 26 switches, 15 modals, 151 alert sites, 22 loading indicators, 118 stable test IDs, 37 distinct Supabase table/view names, and 34 RPC names across mobile plus the shared API package. Mobile direct code accounts for 35 table/view names and 20 RPC names; the shared API package adds 10 table/view names and 15 RPC names (with overlap).

`PASS` means an automated test currently proves the listed behavior. `PARTIAL` means only a meaningful slice is automated or the screen is covered indirectly. `NOT TESTED` means the behavior still needs an environment or test implementation. `FAIL` is reserved for a reproducible unresolved defect.
