The technical document expressly says that TAK publishes the integration data structure, endpoints, registration method, certificate method, signature method, request/response format, error codes, examples and current versions separately (TECH-2026, Article 31, pp. 53–55). OperiX therefore does not invent those values. Any row marked **TAK DEPENDENCY** remains blocked until TAK supplies or confirms the applicable technical package.

## Status legend

- **COMPLETE** — evidence exists in the current repository and the requirement is enforced or documented.
- **PARTIAL** — a reusable foundation exists, but the TAK requirement is not complete.
- **MISSING** — implementable repository work is absent.
- **UNSAFE** — an existing implementation creates a security or compliance risk and must be corrected.
- **TAK DEPENDENCY** — the requirement needs a TAK-issued value, environment, endpoint, schema, certificate, test or approval, or the official source defers the exact detail to TAK technical documentation.
- **LEGAL REVIEW** — the software can provide a control, but legal interpretation or the applicable taxpayer scenario needs confirmation.
- **NOT APPLICABLE** — conditional sector functionality is not present in the OperiX scope; re-open if that sector is added.

## Immediate blockers and interpretation

1. The current official documents identify the required integration surfaces, but the exact TAK endpoint/schema/signature/authentication/QR verification contract is published separately. OperiX must stop at the provider boundary until that package is supplied or confirmed by TAK.
2. The TAK-issued Unique Fiscalization Code, Software Solution Code/EFS code, Fiscalization Number, EFS Identification Number, certificates, production credentials and production endpoints cannot be generated by OperiX.
3. The repository’s current provider foundation is reusable but not certification evidence. Its mock provider and `operix-fiscal://mock/...` QR value are test-only and must never be shown as TAK verification.
4. Production EFS must remain disabled until the exact code, secure key service, taxpayer installation configuration, TAK testing and formal certification evidence exist.
